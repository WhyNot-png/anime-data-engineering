# P3 · Данные → результат → сайт

## Воспроизводимый вход

В Git хранится числовой срез `research/anime-metrics.csv`: `mal_id`, `type`,
`score`, `scored_by`. Он получен из реального набора Kaggle, без названий,
синопсисов, картинок и иных медиа. Полная версия не скачивается в CI.
В `research/source.json` сохранены URL, имя исходного CSV, SHA-256 архива и CSV,
правило удаления точных дублей и SHA-256 числового среза. Параметры —
`research/parameters.json`. Повторное распространение базы подчиняется
[условиям источника](licenses.md), а не MIT-лицензии кода.

Проверено независимым прямым проходом по полному CSV: число включённых тайтлов
и количество TV совпали с результатами конвейера. Пропуски оценок исключаются,
но не заменяются нулём; дубли по `mal_id` в числовом срезе запрещены.

## Схема и команды

```text
research/*.csv + parameters.json + версия кода/зависимостей
           ↓ content-addressed cache
scripts/experiment.py → evidence.json + summary.csv + chart.html + results.md
           ↓ nox -s site
mkdocs build --strict → site/ → Pages artifact → deploy-pages → HTTP healthcheck
```

```bash
uv sync --locked --group docs
uv run --group docs nox -s site
uv run --group docs mkdocs serve
```

`nox` вызывает научную стадию **до** генератора. Таблица, график и текст
на [странице результатов](results.md) строятся из одного evidence object.
Библиотека графика хранится локально; формулы превращаются из LaTeX в MathML
на этапе сборки. Отдельных запросов на внешние CDN нет.

## Кэширование и корректная инвалидация

Ключ — SHA-256 входного CSV, параметров, кода вычислителя, `uv.lock` и шаблона
графика. Кэш содержит только расчётные факты. Даже при HIT заново формируются
**актуальные** хеш коммита и время сборки: старая дата не выдаётся за новую.
GitHub Actions сохраняет каталог `.cache/experiments` через `actions/cache`;
restore-prefix может вернуть старые файлы, но расчёт использует только точный
content key. Изменение данных/параметров/кода/зависимостей инвалидирует кэш.

Локально выполнено 5 пар запусков. Каждая пара — чистый кэш и повторный запуск
в новом процессе. Время «расчёта» включает подготовку ключа и чтение кэша;
полный процесс также включает запуск Python и выпуск Markdown/JSON/HTML.

| Режим | Расчёт/чтение кэша, медиана мс | Полный процесс, медиана мс |
| --- | ---: | ---: |
| MISS | 46.249 | 85.720 |
| HIT | 1.929 | 41.512 |

[Все измерения](evidence/p3-benchmark.json). Это локальные замеры, **не** выдуманное
время CI/деплоя. На таком маленьком расчёте ускорение всей публикации будет
ограничено временем MkDocs, сети и развёртывания, даже если чтение кэша быстрое.

## Контролируемое изменение исходных данных

На временной копии удалён реальный тайтл `mal_id=1`, версия помечена как
`controlled-demo-without-mal-id-1`. Новые наблюдения не выдумывались.
После теста исходный файл восстановлен. Новый SHA вызвал MISS, HTML графика
и CSV пересозданы из обновлённого evidence.

| Состояние | Тайтлов в анализе | TV на графике | Кэш |
| --- | ---: | ---: | --- |
| Исходный срез | 10627 | 4172 | после первого расчёта HIT |
| Копия без mal_id=1 | 10626 | 4171 | MISS |

Перезапуск: `uv run --group docs python scripts/benchmark_experiment.py`.
Тесты также проверяют реальное изменение CSV, обновление параметров и отсутствие
пересчёта только при точном совпадении ключа.

!!! warning "Что ещё требует публичного развёртывания"
    Локальная проверка изменения данных не подменяет демонстрацию
    **изменение → push → обновившийся публичный сайт**. Workflow реализует эту цепочку
    для `main`, но факт публикации и следующий push должны подтверждаться реальными
    запусками после включения Pages и слияния PR. До этого они не заявляются выполненными.

## Связь результата с версиями

Каждая сборка показывает полный git SHA, UTC-время, версию набора, SHA-256 входа,
ключ и HIT/MISS. Машинное представление — `generated/evidence.json`, числовые
агрегаты — `generated/summary.csv`. Тег `lab1` остаётся историческим срезом
заданий 1–2 и не перемещается.

## Ограничения

Число тайтлов — не число уникальных зрителей. Оценки отобраны по порогу голосов,
поэтому различия средних отражают и отбор. Это описательная статистика по снимку,
а не причинный эксперимент и не актуальное состояние MyAnimeList на дату сборки.
Полная загрузка Kaggle, GPU и тяжёлые вычисления не входят в CI.
