# Поиск аниме по описанию с помощью эмбеддингов

Это **семантический поиск по каталогу**, а не генератор названий и не обещание
угадать единственный правильный ответ. Пользователь описывает сюжет своими словами;
программа возвращает ближайшие по смыслу синопсисы и названия аниме.

## Как это работает

1. Из CSV читаются название, синопсис и, если есть, жанры/темы.
2. Предобученная многоязычная модель
   [`intfloat/multilingual-e5-base`](https://huggingface.co/intfloat/multilingual-e5-base)
   превращает описание каждого аниме в вектор.
3. Нормализованные векторы float32 и метаданные сохраняются **в отдельную SQLite БД**.
4. Текст пользователя обрабатывается той же моделью. Префиксы E5 соблюдены:
   `passage:` для каталога, `query:` для запроса, в том числе русскоязычного.
5. Полный перебор векторов и косинусное сходство определяют top-k кандидатов.
   При нормированных векторах cosine равен их скалярному произведению.

В модели зафиксирована ревизия `d128750597153bb5987e10b1c3493a34e5a4502a`.
Обучать нейросеть с нуля, подключать платный API или создавать токен **не нужно**.
Модель работает на CPU и выдаёт 768-мерные векторы. Первый запуск скачивает
около 1 ГБ весов с Hugging Face; далее поиск
выполняется локально при наличии кэша модели. Тексты запросов не отправляются в API.
Загрузка удалённого кода модели отключена (`trust_remote_code=False`).

## Быстрый старт: небольшой учебный каталог

Из корня репозитория:

```bash
uv sync --locked
uv pip install --index-strategy unsafe-best-match -r requirements-search.txt
uv run --no-sync rg anime index examples/anime-search-demo.csv --output data/processed/anime_search_demo.db
uv run --no-sync rg anime search "Парень находит тетрадь: если записать в неё имя человека, он умирает" --index data/processed/anime_search_demo.db --top-k 3
```

Для этого примера ожидаемый кандидат — **Death Note**. В выводе будут также другие
ближайшие варианты. Это проверка работоспособности, а не независимая оценка качества
на всём каталоге.

`examples/anime-search-demo.csv` содержит восемь коротких, заново сформулированных
учебных описаний на английском. Это не копия датасета MyAnimeList. Русский запрос
показывает работу межъязычного поиска, а не буквального совпадения слов.

Машиночитаемый вывод:

```bash
uv run --no-sync rg anime search "Пираты ищут сокровище, у главного героя резиновое тело" --index data/processed/anime_search_demo.db --json
```

Каждый результат содержит `anime` (`id`, `title`, `synopsis`, `genres`, `themes`)
и `score` — косинусное сходство. **Это не вероятность и не процент уверенности.**

## Локальный сайт

С теми же установленными зависимостями запустите:

```bash
uv run --no-sync rg anime serve --index data/processed/anime_search_demo.db
```

Откройте **http://127.0.0.1:8000** в своём браузере. Терминал оставьте работающим.
Введите описание или нажмите один из примеров. Число записей берётся из фактически
выбранного индекса: демо показывает 8, полный каталог — число пригодных уникальных
записей, а не количество строк исходного CSV.

После построения полного индекса достаточно:

```bash
uv run --no-sync rg anime serve
```

Если получили готовый приватный ZIP с индексом, распакуйте его **в корень проекта**:
внутри должен появиться `data/processed/anime_search.db`. Скачивать исходный CSV
и заново считать эмбеддинги в таком случае не нужно. Веса модели в архив не входят:
при первом старте сайт скачает их сам. Проверьте SHA-256 по приложенному manifest,
если хотите убедиться в целостности файла.

**Это не сайт в интернете.** Адрес `127.0.0.1` работает на том компьютере, где
запущена команда. Сервер намеренно слушает только loopback, не `0.0.0.0`.
Не публикуйте порт через туннели/прокси без отдельной настройки безопасности.
Остановка — **Ctrl+C**. Другой порт: `rg anime serve --port 8001`.

Модель загружается один раз на запуск сервера. Запросы обрабатываются последовательно;
при параллельном запросе API отвечает 429. Синопсисы показываются на языке источника.
Веб-часть использует стандартную библиотеку Python и не добавляет новых зависимостей.
JSON API принимает только same-origin POST; есть проверка Host/Origin, лимит тела,
валидация ввода и CSP без inline-скриптов. Каталог и запросы не публикуются наружу.

**Каталог не ограничен релизами 2025 года:** July 2025 — обозначение снимка
MyAnimeList. В нём есть тайтлы разных лет, в том числе значительно более старые.
Это также не живой каталог: новые записи после снимка автоматически не добавляются.

## Реальный каталог MyAnimeList

Источник проекта:
[MyAnimeList Anime Database — July 2025](https://www.kaggle.com/datasets/sazzadsiddiquelikhon/myanimelist-anime-database-july-2025).
Скачайте CSV согласно условиям источника и поместите его в `data/raw/anime.csv`.
Проверенная выгрузка содержит поля `mal_id`, `title`, `synopsis`, `genres`, `themes`.
Для поиска не нужна промежуточная конвертация в Parquet.

```bash
uv run --no-sync rg anime index data/raw/anime.csv
uv run --no-sync rg anime search "Охотники за головами путешествуют между планетами на космическом корабле" --top-k 5
```

По умолчанию индекс находится в `data/processed/anime_search.db`.
Исходная `anime.db` старого ETL не меняется. Повторная команда `index` полностью
перестраивает именно поисковый индекс. Построение атомарное: если кодирование
завершилось ошибкой, прежний индекс остаётся доступен. Посторонние/невалидные файлы
программа перезаписывать отказывается — выберите новый путь.

Размер пачки можно уменьшить при нехватке памяти:

```bash
uv run --no-sync rg anime index data/raw/anime.csv --batch-size 8
```

В полном каталоге обработка на CPU занимает заметно больше времени, чем в демо;
точное время зависит от компьютера. Скачанные веса, исходный датасет и построенные
индексы не должны коммититься. Существующие правила `.gitignore` исключают каталоги
`data/raw` и `data/processed`, кроме `.gitkeep`. Учитывайте условия лицензии данных
и отдельные права авторов синопсисов, описанные в README и LICENSE-CONTENT.md.

### Поддерживаемые входные колонки

Имена нечувствительны к регистру; пробелы/знаки нормализуются в `_`.

| Данные | Поддерживаемые имена |
| --- | --- |
| Название (обязательно) | `title`, `name`, `romaji_title`, `title_english`, `english_name` |
| Описание (обязательно) | `synopsis`, `description`, `summary`, `sypnopsis` |
| Идентификатор | `mal_id`, `anime_id`, `id`, `uid` |
| Жанры | `genres`, `genre` |
| Темы | `themes`, `theme` |

Строки без названия/синопсиса и с заглушками вроде `Unknown` пропускаются с подсчётом.
Для повторных ID берётся первая пригодная строка. При отсутствии ID используется
стабильный хеш названия и синопсиса. CSV с неоднозначными названиями колонок или без
обязательных полей отклоняется. Очистка убирает HTML и лишние пробелы.

## Структура реализации

- `src/research_graph/semantic_search.py` — чтение каталога, нормализация,
  атомарная запись SQLite, валидация индекса и точный top-k по cosine;
- `src/research_graph/embedding.py` — ленивое подключение sentence-transformers,
  фиксированная модель/ревизия, CPU и префиксы E5;
- `src/research_graph/search_cli.py` — подкоманды `rg anime index/search`;
- `tests/test_semantic_search.py`, `test_embedding.py`, `test_search_cli.py` —
  автономные тесты без сети и скачивания весов.

Необязательные зависимости поиска зафиксированы отдельно в `requirements-search.txt`.
Основной `pyproject.toml` и `uv.lock` не меняются: прежний ETL, CLI и лабораторные
сохраняются. Файл requirements использует официальный CPU-индекс PyTorch и маркеры
платформ: Linux/Windows получают CPU-сборку без CUDA, macOS — стандартную сборку.
`--index-strategy unsafe-best-match` разрешает выбирать указанные версии между двумя
официальными источниками (PyPI и PyTorch), а не останавливаться на первом индексе.

После установки зависимостей запускайте поиск с `uv run --no-sync`, чтобы uv
не пересобирал основной environment без необязательных библиотек. Если вы выполнили
`uv sync` и библиотеки поиска были удалены, повторите команду `uv pip install` выше.

## Проверки и границы первой версии

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
uv run --locked pytest
```

Автотесты подменяют модель предсказуемым кодировщиком и проверяют математику,
поиск, пропуски/дубликаты, несовпадение модели, повреждённый индекс, CLI и безопасную
перестройку. Они **не доказывают качество нейросетевого поиска**.
Для smoke-проверки реальной модели используйте команды демо выше и:

```bash
uv run --no-sync python scripts/smoke_anime_search.py --index data/processed/anime_search_demo.db
```

Скрипт проверяет четыре конкретных запроса: тетрадь, девятихвостый лис, пираты и
девочка в мире духов. Он предполагает наличие соответствующих MAL ID в индексе.
При реализации модель также проверена на подвыборке 200 наиболее популярных
по `members` записей реального CSV: эти четыре правильных тайтла оказались первыми.
Это ручной smoke-контроль нескольких характерных случаев, **не оценка точности
на всём каталоге** и не гарантия для других описаний.

Ограничения:

- Нужное аниме должно присутствовать в каталоге и иметь пригодный синопсис.
- Общие запросы («школа, магия, друзья») дают несколько правдоподобных вариантов.
- Деталь, которой нет в синопсисе, может не найтись; длинные тексты обрезаются моделью.
- Система всегда возвращает ближайшие варианты, даже если точного совпадения нет.
  Порог «ничего не найдено» требует отдельной калибровки на размеченных запросах.
- В MVP используется точный перебор `O(N × d)`, а не приближённый векторный индекс.
  Для большого каталога можно перейти на FAISS или PostgreSQL + pgvector.
- Доступны CLI и локальный сайт; публичный хостинг не настраивается.

Следующий шаг для научной оценки — собрать независимый набор описаний с правильными
ID и измерить, как часто правильный ответ попадает в top-1/top-5. Примеры из демо
нельзя выдавать за репрезентативную оценку всего датасета.

## Проверка на полном индексе

Полный индекс содержит 23 551 уникальную пригодную запись из проверенного CSV.
В четырёх вручную выбранных русскоязычных запросах канонические Death Note, Naruto,
One Piece и Spirited Away оказались на местах 1, 2, 6 и 8 соответственно.
Поэтому сайт по умолчанию показывает **10 вариантов**; количество можно изменить.
Это честный baseline семантического поиска, а не точное распознавание названия.
Четыре примера не являются репрезентативной оценкой качества.

`smoke_anime_search.py` по умолчанию проверяет попадание в top-10; другой предел
можно задать `--top-k 5`. Проверка попадания в top-5 на полном каталоге не проходит
для всех этих примеров — не путайте успешную выдачу кандидатов с точностью top-1.

Для улучшения качества потребуется отдельная размеченная выборка и эксперименты
с моделями/ранжированием. Поиск может не найти подробность, отсутствующую в синопсисе.
