# T1 · Какой генератор выбрать для результатов экспериментов

## Вывод и область применимости

Для **этого Markdown-отчёта о небольшом ETL-эксперименте** выбран **MkDocs Material**:
достаточно отдельной воспроизводимой стадии Python + nox, локального поиска и простой
строгой сборки. Это не универсальное превосходство: если нужны автоматические
сквозные ссылки на десятки уравнений, рисунков и публикационный PDF, **Sphinx + MyST**
предпочтительнее. Pelican удобен для хронологического исследовательского блога;
Nikola — для многоязычного блога, смешанных исходников и зависимостной сборки.

Сравниваются Python-генераторы **MkDocs + Material, Sphinx + MyST-Parser, Pelican и Nikola**.
Версии реального стенда: mkdocs 1.6.1; mkdocs-material 9.7.7; Sphinx 8.2.3; myst-parser 4.0.1; pelican 4.11.0.post0; Nikola 8.3.3. Новейшие релизы и использованный lock не тождественны.

## 1. Научный контент: матрица возможностей

Обозначения: **В** — встроено/штатная настройка; **Р** — расширение; **С** — свой скрипт
или HTML. Возможность по документации не означает, что все плагины проверены в эксперименте.

| Критерий | MkDocs Material | Sphinx + MyST | Pelican | Nikola |
| --- | --- | --- | --- | --- |
| Форматы | В: Markdown; Р: `.ipynb`; reST/MyST не штатные | В: reST и MyST; Р: MyST-NB для `.ipynb` | В: reST; Markdown через extra; ноутбуки через reader-плагин | В/компиляторы: reST, Markdown, `.ipynb`; настройки компиляторов обязательны |
| `.qmd` | Не штатный; предварительный Quarto render | Не штатный; предварительная конвертация | Не штатный | Не штатный |
| LaTeX-формулы | Р: arithmatex + MathJax/KaTeX; в нашем сайте build-time MathML | В: math-директивы + `sphinx.ext.mathjax`, `:label:` и `eq` | Р: math-rendering/Markdown extension + JS | В: `has_math`, MathJax; `USE_KATEX` переключает движок |
| Нумерация, ссылки, amsmath | JS/плагин/С; автоматической общей модели ссылок Sphinx нет; MathJax поддерживает AMS | В: `math_number_all`, `math_numfig`, `numfig`, метки; MyST `amsmath` расширяется настройкой | С/расширение; AMS зависит от JS, не от Pelican | AMS и номера зависят от MathJax/KaTeX-конфигурации; глобальные документные ссылки не эквивалентны Sphinx |
| Рисунки, подписи, ссылки, подрисунки | Подпись HTML/Markdown; номера/перекрёстные ссылки Р/С; подрисунки grid/HTML | В: figure, caption, `numfig`/`numref`; подрисунки Р (`sphinx-subfigure`) или grid | HTML/reST подписи; глобальная нумерация и подрисунки С | reST figure/галереи; подрисунки шаблонами; сквозная нумерация С |
| Таблицы, объединения, длинные таблицы | GFM без merge; merge через HTML; широкие таблицы прокручиваются; CSV/DataFrame — стадия Python | reST grid/list/csv-table; объединения в grid; LaTeX longtable; DataFrame предварительно в CSV/reST | reST/HTML merge; длинные HTML-таблицы; CSV/DataFrame скриптом | reST/HTML; merge/длинные таблицы по формату; CSV/DataFrame скриптом |
| Plotly / Bokeh / Altair | Сохранённый HTML/JS встраивается; нужен совместимый lifecycle страницы | HTML через `raw`/расширение; для PDF требуется статический fallback | HTML в статье/шаблоне | HTML в посте/ноутбуке/шаблоне |
| Исполнение и кэш | Ядро не исполняет Python; Р mkdocs-jupyter или С nox/Makefile + content hash (наш P3) | MyST-Parser сам не исполняет; Р MyST-NB/Jupyter-cache | Ядро не исполняет ноутбуки; отдельная стадия nbconvert/papermill | Компилятор ipynb публикует сохранённые outputs; реисполнение/кэш вычислений надо настраивать отдельно, не путать с doit-кэшем HTML |
| BibTeX / стили / список литературы | Р `mkdocs-bibtex` либо генерация Markdown; не встроено | Р `sphinxcontrib-bibtex`: BibTeX, стили, bibliography | Плагин/внешний конвертер; не штатный BibTeX pipeline | reST citations есть, BibTeX/стили — внешняя обработка/плагин |
| Сноски / глоссарий / обозначения / номера разделов | footnotes extension; глоссарий/обозначения Markdown; сквозные номера Р/С | В: footnotes, glossary, numbered toctree; обозначения директивой/списком | Сноски в исходном формате; глоссарий/номера С | Сноски в исходном формате; термины reST; сквозные номера документа С |

Источники: [Material: математика](https://squidfunk.github.io/mkdocs-material/reference/math/),
[MyST: директивы и роли](https://myst-parser.readthedocs.io/en/latest/syntax/roles-and-directives.html),
[Sphinx: нумерация, шаблоны, поиск](https://www.sphinx-doc.org/en/master/usage/configuration.html),
[Pelican: исходники](https://docs.getpelican.com/en/latest/content.html),
[Nikola handbook](https://getnikola.com/handbook.html).

### Цена интерактивности

Измерен **несжатый JS и gzip этого же JS**, а не вес всей страницы. 1 КиБ = 1024 байта.
Для Altair в браузере нужны Vega + Vega-Lite + Vega-Embed; их расходы суммируются.
Bokeh — JS из установленного INLINE, Plotly — `get_plotlyjs()` исследовательского окружения.
Это ориентир стоимости выбранного комплекта, а не нижняя граница для всех bundle-вариантов.

| Комплект | JS, КиБ | gzip JS, КиБ |
| --- | ---: | ---: |
| Chart.js 4.4.1 | 200.3 | 67.7 |
| Plotly 7.1.0 (исследовательское окружение) | 4702.9 | 1434.5 |
| Bokeh 3.10.1 (исследовательское окружение) | 4242.1 | 1269.5 |
| Vega 5 | 503.2 | 173.6 |
| Vega-Lite 5 | 246.3 | 77.4 |
| Vega-Embed 6 | 59.2 | 20.4 |

[Сырые измерения](evidence/interactive-weight.json). Runtime выбранной библиотеки один
для всех четырёх SSG; генератор не делает Plotly «лёгким». Подключение одного bundle
на несколько графиков экономит дублирование. Наш P3 использует локальный Chart.js,
а не Plotly: сложная интерактивность для счётчиков по формату не требуется.

## 2. Вёрстка и шаблоны

| Критерий | MkDocs Material | Sphinx + MyST | Pelican | Nikola |
| --- | --- | --- | --- | --- |
| Колонки и мобильный экран | Material grid/cards; CSS grid перестраивается по ширине | Р sphinx-design grid/cards, responsive breakpoints | HTML/CSS своей темы | Bootstrap grid/HTML своей темы |
| Свой шаблон и overrides | Jinja2; `custom_dir`, переопределение блока без форка | Jinja2; `templates_path`, наследование темы | Jinja2; `THEME`, `THEME_TEMPLATES_OVERRIDES`/выбор template | Mako или Jinja2; локальные templates наследуют тему |
| Несколько представлений | Основной HTML; PDF плагином/печать браузером, LaTeX не native | HTML + LaTeX и PDF при установленном TeX; тема печати | HTML; PDF/LaTeX внешним конвейером | HTML; PDF/LaTeX внешней конвертацией |

Универсального «числа layout-ов» нет: оно зависит от темы, плагинов и включённых
генераторов страниц. Чтобы дать проверяемое число, посчитаны **файлы верхнего уровня
тематического каталога** в зафиксированных пакетах. В счёт входят служебные partials,
поэтому это **не** число семантически независимых layout-ов и не рейтинг качества.

| Тема/база | Шаблонов по этой методике | Файлы |
| --- | ---: | --- |
| Material | 6 | `404.html`, `base.html`, `blog-post.html`, `blog.html`, `main.html`, `redirect.html` |
| Sphinx basic | 14 | `defindex.html`, `domainindex.html`, `genindex-single.html`, `genindex-split.html`, `genindex.html`, `globaltoc.html`, `layout.html`, `localtoc.html`, `page.html`, `relations.html`, `search.html`, `searchbox.html`, `searchfield.html`, `sourcelink.html` |
| Pelican simple | 14 | `archives.html`, `article.html`, `author.html`, `authors.html`, `base.html`, `categories.html`, `category.html`, `index.html`, `page.html`, `pagination.html`, `period_archives.html`, `tag.html`, `tags.html`, `translations.html` |
| Nikola bootstrap4 | 9 | `authors.tmpl`, `base.tmpl`, `base_helper.tmpl`, `index_helper.tmpl`, `listing.tmpl`, `pagination_helper.tmpl`, `post.tmpl`, `tags.tmpl`, `ui_helper.tmpl` |

[Полный машинный протокол](evidence/templates.json). Типичные представления:
Material — документ, блог, 404, redirect; Sphinx — документ, индекс, поиск;
Pelican — статья, страница, архив, автор, категория, тег; Nikola — пост, архив,
галерея, листинг. Наследование может добавлять шаблоны сверх приведённого счётчика.

## 3. Эксплуатация

| Критерий | MkDocs Material | Sphinx + MyST | Pelican | Nikola |
| --- | --- | --- | --- | --- |
| Версии | Р mike, алиасы и selector | Р sphinx-multiversion, селектор темы | Отдельные каталоги/release-ветки | Отдельные каталоги/скрипт; это не версии постов |
| Локальный поиск по-русски | lunr + lunr-languages, `lang: [ru,en]`; стемминг, не полноценная морфология | встроенный индекс, `html_search_language='ru'`, stemming | В ядре нет сопоставимого локального поиска; Р/свой индекс | Локальный поиск через плагин/свой индекс, язык и стеммер проверять отдельно |
| i18n | Перевод интерфейса В; контент Р i18n/каталоги | gettext/locales, перевод интерфейса и сообщений | Метаданные `lang`/translation, шаблоны | TRANSLATIONS и языковые файлы, перевод сообщений |
| Docstrings | Р mkdocstrings | В `sphinx.ext.autodoc` | Внешняя генерация/расширение | Внешняя генерация/расширение |
| Расширения | Python plugins, hooks, Markdown extensions | extensions, roles, directives, builders | signals, readers, generators, Jinja | plugins, compilers, filters, doit tasks |
| Лицензия инструмента | MkDocs BSD-2-Clause, Material MIT | Sphinx BSD-2-Clause, MyST MIT | AGPL-3.0 | MIT |

Стемминг объединяет некоторые словоформы, но не гарантирует совпадение
«регрессия»/«регрессионный»: разные основы могут остаться разными токенами.
Проверка нашего поиска описана в [общем отчёте](report.md), без обещания полной морфологии.
[Material search](https://squidfunk.github.io/mkdocs-material/setup/setting-up-site-search/)
и [Sphinx search](https://www.sphinx-doc.org/en/master/usage/configuration.html#confval-html_search_language).
Лицензия генератора не назначает автоматически лицензию написанному автором контенту.

### Зрелость, активность и доступность

Все четыре проекта имеют длительную историю использования; даты **последнего
релиза PyPI на момент проверки** приведены отдельно от версий бенчмарка.
Это индикатор релизной активности, не замена анализу коммитов/поддержки плагинов.

отечественным хостингом). HTTP 200 не доказывает наличие каждого wheel/хэша:

## 4. Реальные замеры сборки

Стенд: Python 3.12.12, Linux. В каждом проекте 12 эквивалентных
текстовых страниц, таблица и листинг. По 3 запуска, приведена медиана. «Холодная»
означает удаление результата и кэша SSG, **не** сброс дискового кэша ОС и не установку
пакетов. «Повторная» — новый процесс после изменения одной страницы; где генератор
не имеет полноценной incremental-модели, это повторный build, а не обещанная
частичная пересборка. Темы разные; полный научный стресс-тест P2 здесь не заявляется.

| Генератор | Чистая сборка, с | После правки страницы, с | HTML страницы, КиБ | Результат сайта, КиБ |
| --- | ---: | ---: | ---: | ---: |
| mkdocs | 0.398 | 0.392 | 17.38 | 2849.12 |
| sphinx | 0.657 | 0.541 | 9.98 | 324.73 |
| pelican | 0.302 | 0.295 | 8.68 | 307.34 |
| nikola | 0.602 | 0.509 | 10.11 | 1100.96 |

[Все запуски, версии и среда](evidence/ssg-benchmark.json).
Sphinx `.doctrees` исключены из размера публикации. Больший объём Material —
реальный компромисс за интерфейс и поиск, а не преимущество по всем показателям.
Перезапуск: `uv run --group docs --group benchmark python scripts/benchmark_ssg.py`.

## 5. Оценки, веса и выбор

Шкала: **0** — практически не подходит; **1** — значительная ручная работа;
**2** — расширение/дополнительная настройка; **3** — низкая трудоёмкость именно
в данном проекте. Балл **не означает** «всё встроено»: механизмы описаны в матрицах выше.
Веса суммируются до 100; итог = сумма(вес × балл / 3).

Для небольшого отчёта о data engineering важны обслуживание CI (20),
воспроизводимая вычислительная стадия (13) и локальный поиск (9).
Полиграфический PDF (1), сложные формулы/подрисунки/BibTeX (по 2) здесь вторичны:
мы не готовим монографию. В блоке стоимости сборки Material и Sphinx получили
одинаковую среднюю оценку: первый быстрее на стенде, второй заметно компактнее.
